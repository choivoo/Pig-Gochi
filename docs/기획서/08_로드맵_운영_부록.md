# 08. 개발 로드맵, 테스트, 운영, 리스크, 부록

## 1. 개발 로드맵

### 1.1 마일스톤 개요

| 단계 | 기간(1인 파트타임 기준) | 목표 | 산출물 |
|---|---|---|---|
| M0. 사전 준비 | 1주 | 저장소 정리, 기술 스택 확정, 배포 파이프라인 | 빈 프로젝트가 GitHub Pages에 배포됨 |
| M1. 물리 프로토타입 | 2~3주 | 튕기기·충돌·낙사 "손맛" 검증 | 플레이 가능한 단일 책상 데모 |
| M2. 전투 코어 | 3~4주 | 턴, HP, 데미지, 따먹기, AI 기초 | 1v1 전투 완성 |
| M3. RPG 코어 | 3~4주 | 스탯, 레벨업, 스킬, 장비, 세이브 | 육성 가능한 지우개 |
| M4. 콘텐츠 Alpha | 4~6주 | 챕터 1~2, 적 10종, 보스 2종 | 알파 빌드 |
| M5. 메타 시스템 | 3~4주 | 상점, 뽑기, 도감, 일일 콘텐츠 | 리텐션 루프 |
| M6. 폴리시 | 3~4주 | 아트/사운드 교체, 연출, UI 개선 | 베타 빌드 |
| M7. 콘텐츠 완성 | 4~6주 | 챕터 3~6, 로그라이크 모드 | 릴리스 후보 |
| M8. 테스트/최적화 | 2~3주 | 크로스 디바이스, 성능, 밸런스 | v1.0 |
| M9. 출시/운영 | 지속 | 이벤트, 업데이트, 커뮤니티 | v1.x |

총 예상: 약 6~8개월(1인), 팀 3인(개발/아트/사운드)이면 3~4개월.

### 1.2 M1 상세: 물리 프로토타입 완료 기준 (가장 중요)

"재미의 핵심은 튕기는 손맛" 이므로 M1에서 아래를 통과하지 못하면 다음 단계로 가지 않는다.

- [ ] 드래그 → 발사가 직관적이고 정밀하다 (테스트 플레이어 5명 중 4명이 설명 없이 조작).
- [ ] 충돌 반응이 자연스럽고 지우개의 무게감이 느껴진다.
- [ ] 낙사 직전 아슬아슬 상황이 자주 발생하고 짜릿하다.
- [ ] 모바일에서 60fps (중급 기기).
- [ ] "한 판 더" 하고 싶은 느낌 (5판 이상 자발적 연속 플레이).

### 1.3 MVP 정의 (최소 출시 가능 버전)

- 지우개 6종, 스킬 12종, 장비 15종
- 챕터 1~2 (20스테이지) + 보스 2
- 기본 상점, 일반 뽑기, 도감
- 세이브/내보내기, 설정, PWA
- 한국어

MVP 후에 챕터, 모드, 이벤트를 순차 추가한다(라이브 서비스형 업데이트).

### 1.4 첫 2주 상세 실행 계획 (즉시 착수용)

**1주차**
1. 저장소 정리: 기존 `index.html`(트램펄린 카운터) 처리 방침 결정(별도 폴더 보관 or 삭제).
2. `npm create vite@latest` (TypeScript), Phaser 3 + Matter.js 설치.
3. GitHub Actions 배포 워크플로 작성 → Pages 설정 → "Hello Eraser" 화면 배포 확인.
4. `.gitignore`, ESLint, Prettier, Vitest 기본 세팅.

**2주차**
1. 책상 배경 + 지우개 1개 + 드래그 발사 구현.
2. 바디 파라미터를 JSON에서 읽어 즉시 튜닝(개발 중 dat.GUI/Tweakpane 패널).
3. 지우개 2개 충돌, 낙사 판정, "아슬아슬" 이펙트.
4. 모바일 실기기 테스트(같은 와이파이에서 dev 서버, 또는 Pages 배포 링크).

## 3. 품질 관리 (QA)

### 3.1 테스트 체크리스트 (릴리스 전)

**기능**
- 모든 스테이지가 클리어 가능한지(봇 시뮬레이션 + 수동)
- 세이브/로드/마이그레이션/내보내기·가져오기
- 뽑기 확률 통계 검증(100만 회 시뮬레이션 편차 허용 내)
- 경제 시뮬레이션: 무과금 플레이 타임 대비 성장 속도

**호환성**
- iOS Safari 15+, Android Chrome 최신 -2 버전, 삼성 인터넷, 데스크톱 Chrome/Edge/Firefox/Safari
- 화면 비율 4:3 ~ 21:9, 노치/펀치홀 세이프 에어리어 대응
- 가로/세로 회전, 분할 화면

**성능**
- 첫 로딩 3초 이내(4G 환경), 전투 평균 FPS, 메모리 누수(30분 연속 플레이)
- 배터리 소모(저전력 모드에서 FPS 제한 대응)

**접근성**
- 색약 시뮬레이터, 스크린리더 적용 가능한 메뉴(ARIA), 대비비 4.5:1

## 4. 운영 계획

### 4.1 업데이트 주기

- 핫픽스: 필요 시 즉시(GitHub Actions로 수 분 내 배포)
- 정기 업데이트: 격주 소규모(밸런스, 신규 지우개 1~2종)
- 시즌 업데이트: 분기별(신규 챕터/모드/이벤트)

### 4.2 버전 관리 규칙

- SemVer: `MAJOR.MINOR.PATCH` (예: 1.2.0). 화면 하단에 버전 표시.
- 브랜치: `main`(배포), `develop`(통합), `feature/*`. PR 기반 + CI 통과 필수.
- 릴리스 노트는 GitHub Releases에 작성하고 게임 내 "소식" 탭에서 표시(정적 JSON `news.json` fetch).

### 4.3 커뮤니티

- GitHub Issues를 버그 제보/건의 채널로 활용(템플릿 제공), 디스코드/카카오 오픈채팅 선택.
- 인게임 "제보하기" 버튼 → 사전 입력된 이슈 링크(기기 정보, 버전, 세이브 요약 첨부 옵션).
- 팬아트/지우개 디자인 공모 이벤트 → 우수작을 실제 스킨으로 채택(저작권 동의 필수).

### 4.4 마케팅(저예산)

- 숏폼(릴스/쇼츠/틱톡): "실제 지우개 따먹기 vs 게임" 비교 영상, 아슬아슬 모먼트 클립.
- 커뮤니티 홍보: 디시/인벤/레딧(r/WebGames, r/incremental_games 등), 개발일지.
- 학교 시즌(3월 개학, 방학 전) 타이밍.
- "친구에게 도전장" 링크 공유 → 바이럴 루프(고스트 대전 URL).
- 개발 블로그/GitHub README 정비, itch.io 병행 등록(웹 빌드 업로드) 가능.

## 7. 부록

### 7.1 용어집

| 용어 | 정의 |
|---|---|
| 따먹기 | 내 지우개가 상대 지우개 위에 올라타 승리하는 판정 |
| 낙사 | 지우개가 책상 밖으로 떨어지는 것 |
| 아슬아슬 | 낙사 직전 가장자리에 걸려 생존한 상태 |
| 집중력(Focus) | 스킬 사용 자원 |
| 분필 | 프리미엄 소프트 재화 |
| 고스트 | 다른 플레이어의 빌드를 AI가 재현한 대전 상대 |
| 천장 | 일정 횟수 뽑기 시 확정 보상 |
| DDA | 동적 난이도 조절 |

### 7.4 첫 플레이 10분 시나리오 (온보딩 설계)

1. (0:00) 타이틀 터치 → 짧은 컷신(달빛이 책상에) 10초.
2. (0:15) 말랑이 등장. "나를 튕겨줘!" → 화면 중앙에서 손가락 가이드. 빈 책상에서 당겨서 발사 연습. 허수아비에 맞히면 "통쾌한 소리" 보상.
3. (1:00) 두 번째 연습: 가장자리 규칙 설명, 허수아비를 낙사시킴 → "낙사!" 연출.
4. (2:00) 세 번째: 첫 연필 병사 대결. 따먹기 방법 안내(올라타기). 성공 시 큰 연출.
5. (3:30) 첫 보상: 코인 + 장비 "종이 슬리브". 장착 안내(한 번의 탭).
6. (4:30) 1-1 스테이지 정식 진입. 연필 2마리. 클리어.
7. (6:00) 첫 레벨업 → 스탯 포인트 분배 UI 안내(추천 자동 분배 버튼).
8. (7:00) 문방구 뽑기 첫 무료 1회 → 곰돌이 지우개(R) 확정 획득, 도감 등록.
9. (8:30) 1-2 스테이지에서 파티 2인 체험, 스킬 1개 사용 안내.
10. (10:00) "내일 또 와!" 출석 보상 안내, 홈 화면 추가(PWA) 제안, 백업 코드 안내.

### 7.7 결정이 필요한 사항 (오픈 이슈)

1. **게임 정식 명칭**: 가제 "지우개 RPG" → 최종 이름 및 로고.
2. **기술 스택 최종 확정**: Phaser+Matter(권장) vs 순수 Canvas 자체 물리.
3. **기존 `index.html`(트램펄린 카운터)** 처리: 보관/삭제/하위 경로 이전.
4. **커스텀 도메인(CNAME)** 사용 여부.
5. **수익화 여부**: 순수 무료 / 후원 / 광고.
6. **온라인 기능 범위**: 1.0에서 로컬 전용 확정 여부, 2.0 로드맵.
7. **아트 제작 방식**: 직접 / 외주 / 절차적 생성 비중.
8. **세계관 톤**: 현재 유머·귀여움 중심. 다크한 톤은 배제 확정?
9. **세로 우선 vs 가로 우선**: 모바일 세로 UI를 주력으로 할지.

본 기획서의 핵심은 단 하나, **"튕기는 순간의 손맛"** 이다. 모든 RPG 시스템과 메타는 그 손맛을 오래 즐기게 하는 장치일 뿐이다. 따라서 개발은 반드시 **M1 물리 프로토타입**부터 시작하여, 재미가 검증된 뒤에 살을 붙이는 순서로 진행한다. 저장소(`choivoo/Pig-Gochi`)에 GitHub Pages 배포 파이프라인을 가장 먼저 구축해, 개발 첫날부터 링크 하나로 친구들에게 플레이 가능한 상태를 유지하는 것을 권장한다.
